## ⚠️ [validator unavailable] 2026-05-25 23:00 PT — SIGSEGV → elastic-agent zombie: no auto-recovery path

- **Pattern:** C++ SIGSEGV on a single rank → OS D-state workers block TorchElastic from exiting → zombie job, checkpoint CREATING frozen (N=3; cross SEV+post)
- **Surface:** S667567, POST-1332867342141342 (×2)
- **Root mechanism:** SIGSEGV in ServiceRouter stats callback (C++ thread, rank 7) kills the rank's Python process but leaves D-state OS worker threads holding file descriptors. TorchElastic elastic agent is blocked waiting for all workers to exit cleanly — it never does. Result: job appears RUNNING in MAST, metrics stop, checkpoint stays at CREATING/size=0, downstream STUS FULL_SNAPSHOT stalls. NCCL watchdog does NOT fire (this is a C++ crash, not a collective timeout).
- **Detection gap:** Bot classified the outer symptom (RUNNING + 0 metrics + CREATING checkpoint) as P44 GIL hang. This is the same gap as L39 (2026-05-23 m2125081901), which added the disambiguation step to memory but NOT yet to a triage R-rule.
- **Generalization:** Any time D-state rank workers block process-group exit, TorchElastic freezes. The SIGSEGV is the trigger; the zombie is the mechanism. Auto-detection requires: watch for rank pid transitions to D-state AND checkpoint age > N×expected_FS_interval → emit auto-kill. Manual kill is the only current recovery.
