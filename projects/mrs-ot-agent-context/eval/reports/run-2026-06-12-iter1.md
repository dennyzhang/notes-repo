### Candidate 2: Decisiveness (REJECTED — redesign needed)

**Rule**: Require concrete next actions for REAL_OT_FAILURE and NEEDS_INVESTIGATION verdicts.

**Adversarial: REJECT.** Critical finding: `REAL_OT_FAILURE` and `NEEDS_INVESTIGATION` are eval-internal labels (from the eval-flow schema). The live triage agent uses `PAGE / MONITOR / NO_ACTION / THRESHOLD_MISFIT`. The inject_rule's trigger condition never fires on live output → vacuously bypassed.

**Redesign for next run**: Target `PAGE` (action within 30 min) and `MONITOR` verdicts that require a specific investigation step. Also: the eval grader has no `next_action` field — need to add it to GRADE schema and eval grading logic before this dim can improve composite score.

Draft revised rule:
> "DECISIVENESS RULE: For PAGE verdicts (action required within 30 min), always conclude with 1-2 SPECIFIC executable actions naming a concrete entity: a CLI command with actual IDs, a file:line reference, a specific unixname to page, or a specific SEV/task ID. For MONITOR verdicts where a specific investigation step is needed (not auto-resolving P57/P58 cases), include the specific metric or log query to run. Generic 'please investigate' without a named entity = undecisive."
