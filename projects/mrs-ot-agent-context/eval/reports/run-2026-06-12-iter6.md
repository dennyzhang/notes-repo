## Meta-observation: 7 consecutive adversarial rejections on Dec+Own

Every version since iter1 has been rejected at adversarial pre-check or early A/B. The point-fix approach (fix one FATAL → new FATAL emerges from the fix) is not converging. Root cause: prescriptive prose rules that enumerate many branches generate edge cases proportional to their length. v6 (Dec) is now a 300-word rule with 8 clauses; v8 (Own) is 400 words with 10 paths. Each fix introduces 1-2 new FATAL edge cases.

**Strategic pivot for iter7:** Radically simplified rules with minimal branching. See v8 (Dec) and v9 (Own) below.

## Decisiveness v8 design (for iter7 A/B)

Root fix: strip the rule to its minimum. No complex fallback chains. No `meta ai.model describe` in preferred options. One clear entity requirement, one clear gap statement.

> **DECISIVENESS RULE v8:** When `verdict=PAGE` (action required): root_cause MUST name at least one specific entity drawn from the incident body. Valid entities: verbatim MAST job name from the body, verbatim model ID from the body, verbatim upstream SEV ID (format S<digits>) from the body, or a unixname that appears verbatim in the body. Do NOT fabricate any of these. If the incident body contains no MAST job name and no model ID: state "no MAST job name or model ID in body" as the entity gap — this is sufficient. When `verdict=MONITOR` (investigation needed): root_cause MUST reference the specific metric, log command, or entity being monitored from the incident body; generic "please investigate" is insufficient. When `verdict=NO_ACTION`, `verdict=UNKNOWN`, or `verdict=DETECTOR_BROKEN`: no entity required — "alert config fix needed" or "no OT-side action" suffices. Exception: class=NOISE or class=OUT_OF_SCOPE implies verdict=NO_ACTION; these cases require no entity and the entity requirement does not apply.

**Why simpler:** removes the dual-role `meta ai.model describe` (ISSUE 1), eliminates the TRANSIENT/CONVEYOR_REGRESSION MONITOR gap (they follow the general MONITOR rule), and removes the (a)/(b) fallback chain entirely (model describe is no longer part of the rule — it's an agent tool the agent can use, but the rule only cares about what appears in root_cause).

Targeted cases for iter7 A/B: S607776, S657690, S667567, ALERT-1533487445064477 (same 4 as prior Dec A/Bs).

## OwnerRouting v9 design (for iter7 A/B)

Root fix: replace class-label-driven enumeration with body-evidence-driven priority paths. Eliminates the phantom class co-occurrence issue and the fall-through ambiguity.

> **OWNER ROUTING RULE v9:** For `verdict=PAGE` (OT-side action confirmed), apply the FIRST matching path:
>
> **Path A — Upstream cascade:** If the incident body explicitly names an upstream cause (ZippyDB failure, Scribe outage, infrastructure SEV ID): owner = the upstream team named in the body, or "upstream infra oncall" if no team is named. Do NOT infer an upstream team not in the body.
>
> **Path B — STUS retrieval models:** If the incident concerns ig_reels_tab_ss_omni_retrieval or ig_reels_starsearch_t2i_retrieval AND no upstream cause is identified in Path A: owner = `meta ai.model describe --model-id=<model_id_from_body>` using `model_owner` field. If empty → "mrs_ig_retrieval_oncall".
>
> **Path C — Verbatim MAST job name:** If a verbatim MAST job name (pattern mvai-training-online-*) appears in the body: owner = `meta ai.mast-job metadata --name=<verbatim_name>`, try `model_owner_unixname` then `model_owner`. If both empty → "mrs_online_training (pending)".
>
> **Path D — Model ID:** If a model ID (not an entitlement string ending in _prod, _prod_v<N>) appears in the body: owner = `meta ai.model describe --model-id=<model_id>` using `model_owner` field. If empty → "mrs_online_training (pending)".
>
> **Path E — Fallback:** owner = "mrs_online_training (pending model identification)".
>
> For `verdict=MONITOR`: owner = "mrs_online_training (monitoring)".
> For `verdict=NO_ACTION`, `verdict=DETECTOR_BROKEN`: owner = "none (no OT-side action)".
> For `verdict=UNKNOWN`: owner = "mrs_online_training (pending triage)".

**Why simpler:** no class-label routing (eliminates UPSTREAM_INFRA+REAL_OT_FAILURE co-occurrence issue); non-STUS REAL_OT_FAILURE has explicit named fall-through via Paths C/D/E; priority order (first-match) makes precedence unambiguous.

Targeted cases for iter7 A/B: ALERT-1201406268614142, ALERT-1533487445064477, A1703030847735006, ALERT-1427819186056622, S665454 (same 5 as prior Own A/Bs).
