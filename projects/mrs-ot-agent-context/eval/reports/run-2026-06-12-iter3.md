**Adversarial verdict: REJECT — 3 fatal flaws:**

1. **Field-level vocabulary mismatch (primary):** The rule lists `REAL_OT_FAILURE`, `REAL_OT_FAILURE_RECURRING`, `KNOWN_PATTERN` as "verdict labels" but these are `class` field values in the agent's output schema. The actual `verdict` field is `PAGE / MONITOR / NO_ACTION / UNKNOWN`. `REAL_OT_FAILURE_RECURRING` doesn't exist in the schema. An agent can satisfy `verdict=PAGE` without ever triggering the REAL_OT_FAILURE entity requirement. The v1→v2 "fix" swapped eval labels for prod class labels — same vocabulary mismatch, different field.

2. **AWAITING_CONTEXT entity-hallucination trap:** When a SEV title is anonymous (e.g., "OT jobs hanging") the i-pre guard mandates AWAITING_CONTEXT. This label is absent from both the required-entity list AND the exempt list. The agent must either hallucinate a job name to comply (exact S665478 failure mode) or silently fail — no valid path.

3. **CONVEYOR_REGRESSION coverage gap:** A real production class indicating conveyor publish blocked by upstream regression. Not in required-entity list or exempt list — exploitable bypass for an entire incident class.

**Bonus structural issue:** UPSTREAM_INFRA entity form is specified as "CLI command / unixname / file:line" but the correct entity for upstream cascade is a SEV ID (e.g., S668542) — none of those three forms.

---

### Decisiveness v3 redesign (for iter4)

Root fix: target `verdict` field values (the two-value output split) not class values. Also allow SEV IDs as valid entity form.

> **DECISIVENESS RULE v3:** When `verdict=PAGE` (action required): include in root_cause AT LEAST ONE specific entity — a CLI command with ACTUAL IDs verbatim from the incident body (not `<placeholder>` templates), a specific unixname to page, or an upstream SEV ID (e.g., S668542). When `verdict=MONITOR` (investigation needed): include the specific metric query or log command with the ACTUAL job name from the body (not a placeholder). AWAITING_CONTEXT, CONVEYOR_REGRESSION, UPSTREAM_INFRA (cascade-in-progress): entity not required until model identity confirmed. `verdict=NO_ACTION`, DETECTOR_BROKEN, OUT_OF_SCOPE, NOISE, TRANSIENT: "alert config fix needed" or "no OT-side action" suffices — no entity required. If the incident body contains no MAST job name, state that explicitly; do NOT construct one from a model ID or model type.

Targeting 6 cases for v3 A/B: S607776, S622829, S639956, S657690, S667332, S667567 (the 6 SEV mitigated cases where entity presence is verifiable from the ground truth resolution).

### OwnerRouting v4 redesign (for iter4)

Root fix: add REAL_OT_FAILURE branch to STUS exception; add verbatim-only guard for MAST lookup.

> **OWNER ROUTING RULE v4:** For `verdict=PAGE` (OT-side action confirmed):
> - If a verbatim MAST job name (matching pattern `mvai-training-online-*`) appears in the incident body: owner = result of `meta ai.mast-job metadata --name=<verbatim_name>`. Do NOT construct a MAST job name from a model ID — if no verbatim name present, go directly to fallback.
> - Fallback (model_type known, no verbatim MAST name): owner = result of `meta ai.model-series metadata --model-type=<type>`.
> - If model identity is ambiguous: owner = "mrs_online_training (pending model identification)".
>
> For `verdict=MONITOR`: owner = "mrs_online_training (monitoring)".
>
> For `verdict=UPSTREAM_INFRA` (cascade): owner = the upstream oncall rotation handle IF the team is explicitly named in the body (e.g., "ZippyDB oncall" → output "zippydb oncall", not "ZippyDB team"); otherwise = "upstream infra oncall". Do NOT infer or look up SEV status or oncall identity not stated in the body.
>
> For `verdict=NO_ACTION`, DETECTOR_BROKEN, NOISE: owner = "none (no OT-side action; alert config fix needed separately)".
>
> **STUS exception (ig_reels_tab_ss_omni_retrieval, ig_reels_starsearch_t2i_retrieval):**
> - Upstream Scribe/ZippyDB SEV confirmed in body → UPSTREAM_INFRA; owner = upstream SEV oncall from body, NOT PE MRS monitoring.
> - No upstream SEV confirmed in body → REAL_OT_FAILURE (P50 — STUS publish failure); owner via MAST job lookup above.

Case selection for v4 A/B: focus on the 4 regressing cases (A1703030847735006, ALERT-1009946182010606, ALERT-2032923427581795, S665454) + 2 DETECTOR_BROKEN cases (ALERT-1201406268614142, ALERT-1533487445064477) + 2 UPSTREAM_INFRA stable (ALERT-1427819186056622, ALERT-1621571482326635). 8 total — reduced scope to cut noise from non-deterministic baselines.
