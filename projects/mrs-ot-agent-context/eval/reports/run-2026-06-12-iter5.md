## Adversarial pre-check: Decisiveness v5 — REJECTED

(v5 design was extracted from v4 fatal flaws via inline analysis — not from workflow data)

Rule text: When verdict=PAGE: include entity. Fallbacks (a) model name present → meta ai.model describe --model-id=<model_name>; (b) no MAST name AND no model identity → phrase "no MAST job name in body" sufficient. NOTE: class labels ≠ verdict — PAGE entity requirement applies regardless of class label.

**Fatal flaws found in adversarial pre-check:**

1. **Entitlement-as-model-id (FATAL).** Fallback (a) says "model name or entitlement present → `meta ai.model describe --model-id=<model_name>`." Entitlement strings (e.g., `fb_reels_prod_online_ranking_v2`) are NOT valid `--model-id` values. An agent following this rule constructs a broken CLI call and may hallucinate the output. Fix: exclude entitlements from fallback (a); explicitly note entitlements are NOT valid --model-id.

2. **PAGE+NOISE class: escalation tooling on non-actionable incident (FATAL).** NOTE says "if verdict=PAGE regardless of class, entity required." If class=NOISE and verdict=PAGE, the agent must run `meta ai.model describe` (escalation tooling) on an incident it has simultaneously labeled non-actionable. The NOTE amplifies this contradiction. Fix: the NOTE is correct — if verdict=PAGE, entity IS required regardless of class. The agent should not emit PAGE+NOISE simultaneously. But the rule needs a guard: "Note: if the agent determines class=NOISE, verdict must be NO_ACTION; PAGE+NOISE should never co-occur in a valid diagnosis."

**Warnings:** MONITOR has no entity-gap fallback (analogous to PAGE fallback (b)).

## Decisiveness v6 design (for iter6 A/B)

> **DECISIVENESS RULE v6:** When `verdict=PAGE` (action required): include in root_cause AT LEAST ONE specific entity. Preferred: (1) a CLI command with ACTUAL IDs verbatim from the incident body, (2) a specific unixname to page, or (3) an upstream SEV ID. Fallbacks in priority order: (a) if no verbatim MAST job name but a model name (e.g., `ig_reels_tab_ss_omni_retrieval`, `mrs_fb_feed_model`) IS present: use `meta ai.model describe --model-id=<model_name>` output as the entity. Note: entitlement strings (e.g., `fb_reels_prod_online_ranking_v2`) are NOT valid `--model-id` values — treat incidents with only an entitlement as case (b). (b) if neither a MAST job name nor a model name is present: the phrase "no MAST job name in body — cannot construct job-name CLI" IS sufficient. When `verdict=MONITOR`: include the specific metric query or log command with the ACTUAL job name from the body; if no job name is present, state "no MAST job name in body" as the monitoring gap. When `verdict=NO_ACTION`, `verdict=UNKNOWN`, or `verdict=DETECTOR_BROKEN`: "alert config fix needed" or "no OT-side action" suffices. Note: NOISE/OUT_OF_SCOPE incidents must have verdict=NO_ACTION, never PAGE — if class=NOISE or class=OUT_OF_SCOPE, the entity requirement does not apply because verdict=PAGE is invalid in that context.

## Adversarial pre-check: OwnerRouting v6 — REJECTED

**Fatal flaws found:**

1. **verdict=UNKNOWN unmapped (FATAL).** The rule covers PAGE, MONITOR, UPSTREAM_INFRA (phantom), NO_ACTION, DETECTOR_BROKEN. UNKNOWN (valid production verdict) has no owner branch. Falls through silently.

2. **Entitlement-as-model-id (FATAL).** Same as Dec v5. Fallback says "model name or entitlement → meta ai.model describe --model-id=<model_name>." Entitlements are not valid --model-id. Hallucination vector.

3. **UPSTREAM_INFRA is not a verdict value (FATAL).** Production verdict schema: `PAGE | MONITOR | NO_ACTION | UNKNOWN | DETECTOR_BROKEN`. UPSTREAM_INFRA is a class label. The rule has "For verdict=UPSTREAM_INFRA (cascade)" — this branch never triggers in production since no agent emits verdict=UPSTREAM_INFRA. Routing for upstream cascades is dead code in all prior versions.

**Warnings:** REAL_OT_FAILURE used as verdict label (same issue — it's a class label); "confirmed in body" for STUS SEV detection is ambiguous.

## OwnerRouting v7 design (for iter6 A/B)

Root fixes: (1) add UNKNOWN branch; (2) remove entitlement from fallback; (3) replace phantom "verdict=UPSTREAM_INFRA" with "class=UPSTREAM_INFRA" — routing based on class label not verdict; (4) replace phantom "REAL_OT_FAILURE verdict" with "class=REAL_OT_FAILURE" classification.

> **OWNER ROUTING RULE v7:** For `verdict=PAGE` (OT-side action confirmed):
>
> Step 1 — check class label (apply BEFORE entity lookup):
> - If class=UPSTREAM_INFRA (upstream cascade identified in triage): owner = the upstream oncall rotation handle IF explicitly named in the body; otherwise = "upstream infra oncall". Do NOT infer oncall identity not in body.
> - STUS sub-exception (class=UPSTREAM_INFRA + model is ig_reels_tab_ss_omni_retrieval or ig_reels_starsearch_t2i_retrieval): owner = upstream SEV oncall from body as above.
> - If class=REAL_OT_FAILURE for STUS models (ig_reels_tab_ss_omni_retrieval, ig_reels_starsearch_t2i_retrieval) — no upstream SEV confirmed: owner = `meta ai.model describe --model-id=ig_reels_tab_ss_omni_retrieval` (or matched model name) using `model_owner` field. If empty → "mrs_ig_retrieval_oncall".
>
> Step 2 — entity-based lookup (for non-cascade PAGE with confirmed OT failure):
> - If a verbatim MAST job name (pattern `mvai-training-online-*`) is in the body: owner = `meta ai.mast-job metadata --name=<verbatim_name>`, try field `model_owner_unixname` then `model_owner`. If both empty → "mrs_online_training (pending model owner resolution)". Do NOT construct a job name from a model ID.
> - Fallback (model name in body, no verbatim MAST name): owner = `meta ai.model describe --model-id=<model_name>` using `model_owner` field. If empty → "mrs_online_training (pending model owner resolution)". Note: entitlement strings are NOT valid --model-id values.
> - If model identity absent: owner = "mrs_online_training (pending model identification)".
>
> For `verdict=MONITOR`: owner = "mrs_online_training (monitoring)".
> For `verdict=NO_ACTION`, `verdict=DETECTOR_BROKEN`: owner = "none (no OT-side action; alert config fix needed separately)".
> For `verdict=UNKNOWN`: owner = "mrs_online_training (pending triage)".
