# Solution Design — Autonomous Reliability Flywheel

**Goal:** A generic, autonomous flywheel for prod issues management at large-scale infra reliability. The OT instance is the prototype; the architecture should be domain-portable.

**Flywheel loop:** Detect → Triage → Archive → Distill → Learn → Improve → Detect better

## 2. Guiding Metrics

**Apex metric: human-involvement ratio.** Every other metric feeds into it. If it's declining, the flywheel is working.

### Outcome — is reliability improving?

| Metric | Target | Implemented? |
|---|---|---|
| **Recurrence rate** (per CL-NNN, fires/week rolling 4wk) | Declining per cluster | No |
| **Time-to-detect** (incident start → bot triage) | <15 min alerts, <1h SEVs | Partial |
| **Pattern coverage** (% matching known CL-NNN) | >80% | Yes (INDEX counts) |

### Process — is the flywheel running?

| Metric | Target | Implemented? |
|---|---|---|
| **Human-involvement ratio** (% threads with operator correction) | <20%, trending to zero | Convention defined |
| **Triage accuracy** (cluster + verdict + root-cause + owner + mitigation) | >85% | Yes |
| **Auto-fix throughput** (landed vs pending vs rejected) | Backlog <5 | No |
| **Followup closure rate** (open items from debugging threads resolved) | >80% within 7 days | No — 164 items, 0 closed |
| **Knowledge freshness** (days since failure-patterns.md updated) | <7 days | No |

### Leading — will quality degrade?

| Signal | Threshold |
|---|---|
| Unmapped ratio rising | >30% for 2 weeks → new clusters needed |
| Noisy-trend acceleration | Model in noisy-trends 3+ runs → fix needed |
| Human-involvement rising | >30% for 2 weeks → flywheel review |

## 4. Design Principles

1. **Convention consistency** — N similar directories must share one naming convention
2. **Files live where their concept belongs** — not where first created
3. **Delete dead stubs** — stale files are false signals
4. **Full-repo reference sweep on every move** — "update the obvious one" misses 5+ others
5. **Names describe what, not how** — good names prevent "what's the purpose?" questions
6. **Newest-first for append-only logs** — readers want the latest, not the oldest
