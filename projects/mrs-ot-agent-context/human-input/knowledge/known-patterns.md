# Known Patterns DB

64 patterns and 4 red herrings from OT SEV triages. The triage tool matches
error text against these before LLM analysis. Check the Ruled-Out list to
avoid re-investigating known red herrings.

**For the failure-mode taxonomy, GIL/NCCL concept reference, and disambiguator command list, see [`references/ot-failure-mode-catalog.md`](human-input/ot-failure-mode-catalog.md).** Patterns below should map to a class in that taxonomy (A1–A5 job hangs · B1–B3 collective hangs · C1–C5 scheduling · D1–D10 publish · E1–E5 perf · F1–F2 cold start).

**Auto-learn rule:** when the master agent diagnoses an issue whose
cause→symptom→fix triple is not already covered by these patterns,
append a new row here as part of the same triage. See SKILL.md
"Auto-Learn" section for the discipline.

## SEV Validation

Triage journals with detailed findings, tool performance, and gap analysis: [journals/](journals/)

**Triage heuristic:** When triaging an IG model, check quota/admission first — ~42% of IG OT SEVs are quota-related. When multiple models across PGs fail simultaneously, suspect infrastructure (Scribe, ACL, network) before individual components.

**Restart-required recovery is a discriminator:** a genuine upstream data/source outage SELF-recovers once data returns; if a job only recovers after a manual restart, it was left wedged → suspect preemption / scheduling / local-stuck, NOT the data source.

**Synchronized RUNNING-but-0/low-QPS across many jobs/orgs** (jobs stay MAST RUNNING — not DEAD/PENDING like P10): a per-job hang cannot synchronize → a SHARED dependency is the cause. **Check the data-side FIRST: per-mast-job DPP starvation ODS (`fburl.com/canvas/pzoyunzx`) + scribe token ingress (`dpp_stats_v2`)** — a shared upstream scribe/region drain is the most common synchronizer and was the confirmed S674219 root (EAG/DR scribe drain → ~75% DPP ingress drop → 0 ingress fleet-wide; tracked S674227, fix D94521578). Hand DPP/scribe oncall the per-job ODS as evidence. Only if DPP ingress is healthy, consider host-scheduler/elastic-donation (S674182 was a concurrent **red herring** in S674219, NOT the root) → `mast_scheduler`. (1 sample, 2026-06-10.)
