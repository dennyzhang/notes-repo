# P-013: Leadership Asks Need Named Target + Specific Deadline

**Statement:** An "ask" with no named owner (unixname) and no specific deadline is not an ask — it's a wish. Always cite (a) who's accountable and (b) when, in any cross-team escalation.

**Discovered:** 2026-05-16 thread `ZP2y-6Bdpwk` — operator critiquing "scope a project for X" cluster recommendation: no owner = nothing happens.

**Why it matters:** Vague asks evaporate into Slack history. Specific asks (`hkwok by 2026-W22`) create accountability + status-checkable artifacts. The cost of being specific is naming someone you might be wrong about; the cost of vagueness is the ask never landing.

**Applies to:** any agent producing escalation summaries, status briefs, or cross-team recommendations.

**Current applications:**
- failure-patterns.md "Leadership ask" lines: `hkwok` (MVAI AI Infra), `ezrak` (own team), `renqincai` (Threads), `yufengma`/`yzqian` (CFR), `llu6` (OT onboarding), `shuminwu` (manager for cross-workstream)
- All cluster-level asks now have unixname + week deadline
- ot-human-attention-brief surfaces by-week ask deadlines

**Anti-patterns it prevents:**
- "Should scope a project" recommendations with no owner
- "Team should look at this" without naming the team-lead
- Action items in brief that have no follow-up trigger

**Related principles:** P-012 (mitigated vs routed — status claims need owner + evidence), P-005 (conciseness — but specificity beats brevity for asks)
