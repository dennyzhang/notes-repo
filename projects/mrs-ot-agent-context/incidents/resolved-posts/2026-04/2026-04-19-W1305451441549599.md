# [S651642](https://www.internalfb.com/intern/sevmanager/view/s/651642): [IG FEEDS LSR][OT] Persistent StuckJob SEV3 

## Summary

  Online training (OT) for MB8 Feeds LSR combo models is experiencing recurring stuck job failures across both control and test arms. Jobs run for ~1.5-2 hours before a single rank hangs, triggering StuckJobDetector termination. MAST auto-restarts, but the pattern repeats every attempt.

## Affected Jobs

  - mvai-training-online-2127148670 (control, 27 params) — 4 restarts, 600s timeout

  - mvai-training-online-2127162843 (test, 53 params) — 10+ restarts total (8 at 600s timeout, 2 at 1800s timeout)

## Root Cause Analysis

  Two distinct hang points, both in the uhm_preproc / SlimPer tokenizer path:

  **1. Forward pass hang (FORWARD_PASS component)**

  - Location: `dper_lib/slimper_lib/tokenizer/one_feed.py:701` → `torch.unique()` inside `get_unique_embeddings()`

  - Context: Called from `model.py:920 base_forward_local → uhm_preproc` under `torch.compile` (`torch._dynamo`)

  - Affected ranks: 0, 45, 69 (varies per attempt — not a single bad host)

  - Hypothesis: `torch._dynamo` recompilation or CUDA kernel hang when `torch.unique()` encounters dynamic shapes from Scribe streaming data

  - Related proposal: `ENABLE_UHM_1D_DEDUP` (Efficiency Combo)

  **2. Checkpoint metrics sync hang**

  - Location: `torchmetrics/utilities/distributed.py:126` → `torch.distributed.barrier()` inside `gather_all_tensors()`

  - Context: Called during `_save_checkpoint_and_retry_info → _validate_model_state → force_validate_metrics → rec_metric.compute()` → torchmetrics sync

  - Affected ranks: 34, 69, 84 (varies per attempt)

  - Hypothesis: One rank is blocked in the forward pass (hang #1), causing the barrier to stall on all other ranks during the next checkpoint sync

  Both hang points share the same underlying cause: a rank gets stuck in the `torch.compile`'d `uhm_preproc` path, and the stuck propagates to any subsequent distributed collective.

## What We've Tried

  **1. Increased stuck job detection timeout (Experiment C)**

  - Changed `stuck_detection_timeout_secs` from 600s (10 min) to 1800s (30 min) in `OnlineMastConfigProvider._system_config()` in trainer_config.py

  - Commit: `32c74865e702` (rebased on original `bbf87d2c4555`)

  - Re-ran `online_train_publish` for model 2127162843, landed new TLS diff [D101533601](https://www.internalfb.com/diff/D101533601?entry_point=20), killed and re-registered OT

  - **Result: Did not fix.** The hang lasted >30 min (last_renew_time gap = 1806s), exceeding even the 1800s timeout. The underlying hang is real and indefinite, not just a tight timeout window.

  **2. Launched OT without new UHM preproc proposals (Experiment B)**

  - Removed 10 UHM-preproc-related flags from the test params-to-update (43 flags instead of 53)

  - Removed proposals: Efficiency Combo (UHM_1D_DEDUP, EARLY_UNIQUE_LAUNCH, EARLY_EC_LOOKUP), UHM Ladder, FuseUp Part I, UIH Enrichment, SWM-ZeRO, CMSL, Model Reliability (encoding)

  - Launched fresh `train_publish` + `online_train_publish` from original commit: [f1068978067](https://www.internalfb.com/intern/bunny/?q=f1068978067) (SUCCEEDED)

  - **Result: Pending** — OT registration awaiting TLS diff landing

  **3. Verified the issue is not host-specific**

  - Failing ranks differ across attempts: 0, 34, 45, 69, 84

  - All attempts on the same hardware type (T20_GTV1_5_B200_180GB_HBM3E_DSF / GRANDTETON_B200)

  - Rules out bad GPU / NIC on a specific host

  **4. Confirmed checkpoints still progress despite restarts**

  - Model 2127162843: checkpoints 5→9 produced every ~2h

  - Model 2127148670: checkpoints 0→1 produced

  - The model is functional between hangs — stuck jobs are intermittent, not permanent
