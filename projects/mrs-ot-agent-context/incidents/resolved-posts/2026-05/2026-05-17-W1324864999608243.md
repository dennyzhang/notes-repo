## Root cause
`_preload_item_pool()` in `ig_retrieval/trainer.py` (line 332 → serving_aware.py:278) blocks the DPP consumer thread during checkpoint loading startup. DPP workers fill their output queues, but the trainer-side consumer doesn't drain them during item pool preloading → `GetDataTimeoutError` after 6000s timeout → crash loop. Reproducible across 2 regions (vll, ncg) and 9 restart attempts over 21h. Model code bug, not infra. Rudra speculated possible connection to D104469704 but Lan Xue's analysis suggests D104469704 (gloo desync via dist.all_reduce) is a different mechanism.

## Mitigation
1. Kill stuck jobs.
2. Reduce `--preload-batch-size` from 2048→512.
3. Limit item pool partitions: change `ds=*` to specific recent partition.
4. Long-term: enable async item pool reload in model config.
5. Route to `p92_relevance_retrieval` model owner oncall for code-level fix in `ig_retrieval/trainer.py`.
