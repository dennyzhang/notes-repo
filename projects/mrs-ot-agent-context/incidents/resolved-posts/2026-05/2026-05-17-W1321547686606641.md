## Root cause
`checkpoint_training_data_age_mins` alert fires 3000 min for `facebook_reels_vdd_hstu_v0` (model 877766932), but the model is actually healthy: ODS `dpp_worker.scribe_example_age_ms.avg.60` shows ~2.5 min (healthy). The Scuba-derived column has two formula bugs for OT jobs: (1) timezone mismatch — `metric_value` is UTC but `train_end_ts` gets a -7h shift via TIME_ZONE_CONVERTER, injecting a systematic error (known bug D75703936); (2) wrong scope — the alert was designed for *recurring training* workflows, not OT; `train_end_ts` is hour-aligned for OT via `_resolve_ts_now()`, making the derived column architecturally wrong. ODS metric is the correct ground truth.

## Mitigation
**Immediate:** Ignore `checkpoint_training_data_age_mins` for OT jobs; use `dpp_worker.scribe_example_age_ms.avg.60` from ODS instead (MAST ODS Dashboard). **Long-term:** Denny committed to creating a mitigation diff to fix the formula / detector scope. Known bug D75703936 tracks the timezone mismatch.
