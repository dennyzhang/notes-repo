## Root cause
P50 confirmed: SilverTorch STUS models use the GMPP publisher path (Scribe → ZippyDB for metadata), which was blocked during S660017/S660220. In-trainer MVAI models write directly to model store, bypassing GMPP/Scribe, so they were unaffected. The differential impact is a known architectural vulnerability. **Cite P50.**

## Mitigation
Wait for upstream infra SEV (S660017/S660220) resolution. STUS publish auto-resumed on Scribe/ZDB recovery. No OT-side action needed. Long-term: add Scribe health check to GMPP publish path with fast-fail alerting.
