## Root cause
DPP data session has a TTL of 1728000 seconds (~20 days). When TTL expires, DPP automatically restarts each OT job's data session. During the restart, training pauses for a few minutes and example age spikes. The spike is often large enough to trigger UBN/SEV threshold alerts, creating ~280 non-actionable oncall events per half across 50+ models. The session restart is necessary per DPP design (Zeus TTL renewal) but lacks a graceful handoff mechanism.

## Mitigation
Loop in DPP team (`dpp_distributed_data_processing`) for graceful session rotation. Short-term: treat error message "Session <ID> has been running for <N> seconds which is higher than limit: 1728000 seconds" as a known non-actionable signal — suppress or auto-close UBN/SEV alerts triggered by this pattern. Full investigation: https://www.internalfb.com/intern/paste/P2349020385
