## Root cause
Rank 7 of reranker job mvai-training-online-2125081901 hit a SIGSEGV in C++ (ServiceRouter stats callback). The elastic agent (TorchElastic/supervisor) detected the crash but entered D-state (disk sleep / uninterruptible wait) blocked waiting for other ranks to exit cleanly. The zombie job occupied the MAST slot indefinitely — MAST reports RUNNING but Python/training activity has ceased (no mvai_metrics, no new checkpoint). This is an elastic-agent hang, NOT a Python GIL freeze (P44 class A1) despite identical outer symptoms. Downstream consequence: T2I update service for 2132070936 relies on 2125081901 checkpoints to trigger FULL_SNAPSHOT — all FS generation blocked for ~28h.

Note: bot initially classified as P44 (learnings.md L39); Denny corrected to elastic-agent hang. Recovery action identical (kill v + TMS restart) but attribution differs.

## Mitigation
fengzhang1 (mrs_relevance_retrieval_i2i oncall) manually killed v4 of mvai-training-online-2125081901. TMS auto-restarted from checkpoint v608. Once a new valid checkpoint appeared, T2I update service on 2132070936 auto-published FULL_SNAPSHOT. S667567 mitigated 2026-05-24 08:19 PT.
