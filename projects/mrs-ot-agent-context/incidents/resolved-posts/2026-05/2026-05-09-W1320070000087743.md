## Root cause
Delta publishing enabled on a new Facebook IFR QE model causes DPP Hedwig publish backlog pile-up, consuming RAM (75%→OOM). Two root factors: (1) `TORCHINDUCTOR_COMPILE_THREADS=1` was saving CPU memory in earlier MCs but hurting QPS and causing high example age in current MC; (2) memory tables not optimally placed in HBM. Publish limit cannot be raised (data loss risk). Additional capacity not available.

## Mitigation
1. Move some embedding tables to HBM (saves ~3% CPU memory usage).
2. Remove `TORCHINDUCTOR_COMPILE_THREADS=1` from training config (recovering training QPS + reducing example age).
System stabilized at 91% CPU memory — still on the edge; further optimization needed long-term.
