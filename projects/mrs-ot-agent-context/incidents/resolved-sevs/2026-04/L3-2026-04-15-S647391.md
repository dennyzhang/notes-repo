## Overview
Context: 
TMS (Training Management System): Used to keep track of user-intent for a model (Recurring, ONLINE_READY, Expired, Paused) and auto-restart Online Training jobs (new job). Replaced Start Cart
ADHOC: An Online Training started via fire cli by a user and not managed by TMS. This type of job is now registered in TMS.  We track it for the purpose of cleanup and accounting.
Override_prod_validator: MVAI Trainer leverages the follow validator (https://www.internalfb.com/code/fbsource/fbcode/minimal_viable_ai/core/validation/override_prod_validator.py?lines=1) at runtime to avoid accidentally generating snapshots and checkpoints for a prod model from a test job.  (i.e. forgot to change the model id when running the test job). It uses TMS to check a model id is registered in TMS and assumes if registered in TMS, it must be prod and would block snapshot/checkpoint generation and kill the job (assuming the job name of the new mast job is different from the job name registered in TMS)
fire: cli to launch a model training job to MAST for scheduling.  During launch - fire will register the job's model as ADHOC if it is not already in TMS registered as PROD

fire-app-fbr-preranker + fbr_hstu + cfr_main cogwheel blocked — TMS ONLINE_READY rejects -mrs_cog-test- jobs (cross-conveyor, 3 affected)

## Incident impact
3 conveyors blocked at cogwheel test step due to TMS ONLINE_READY rejecting -mrs_cog-test- job names:
mvai/fire-app-fbr-preranker (blocked since R2642, Apr 10)
silvertorch/fbr_hstu (3 failures Apr 13: models 2128028693, 2128026099, 2128023078)
mvai/cfr_main_feed_mtml_roo_hstu (online_train_publish_full_only crash on model 2127987865, Apr 13)
No new trunk releases shipping for these surfaces — model freshness degrading.

## Root cause
D97779093 (landed Mar 23) changed Fire-launched online training jobs to register as ADHOC entries in TMS. Previously, Fire-launched jobs had no TMS entry. The OverrideProdValidator (TMS ONLINE_READY check) did not account for ADHOC model_importance -- it assumed any TMS entry was PROD and rejected cogwheel test jobs with -mrs_cog-test- in the name as unauthorized prod model overrides. 

Walkthrough:
- cogwheel test called fire to launch a new OT training job
- fire registered the OT training job model as ADHOC in TMS
- job is launched with prefix mrs_cog-test-
- cogwheel ot job at runtime hit the override_prod_validator. 
- validator sees 1) job is registered in TMS 2) job name registered in TMS (i.e. mvai-training-online-<modelid>) is different from the current cogwheel job (i.e. mvai-training-online-<model_id>-mrs_cog-test-<id>). 
-Because the validator thinks there's already an existing job running it; it blocked the cogwheel OT job and failed it.

The ~2 week delay between D97779093 landing and SEV manifestation is likely due to timing of conveyor runs and TMS registration propagation.

## Remediation
Apr 10 - AI recommended remediation D100379084 landed — set online_training_eligibility=False for FBR preranker cogwheel test models. TMS ONLINE_READY validator still rejects cogwheel test jobs. Verified in R2606.2: original error. Change did not fully resolve issue

Apr 13 - D100649720 (https://www.internalfb.com/diff/D100649720) - full fix landed - [mvai] Skip override prod check for ADHOC model_importance in TMS
If a model id is registered as ADHOC in TMS; it is not prod - and this validator doesn't apply to it. So it is safe to allow the current job to continue training.

New unrelated failure (Publish failed as empty results from all ranks) is a separate trunk regression affecting multiple OT conveyors.

## Prevention
Account for ADHOC model importance in validator and unittests (T270992803)
Account for other model importance values (not currently used) - but this way we're not caught off guard if suddenly they do get used - i.e. model importance QE, UNKNOWN (T271022563)
