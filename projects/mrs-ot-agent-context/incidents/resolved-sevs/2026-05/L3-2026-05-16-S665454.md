## Root cause
[from gchat + postmortem — VERIFIED via gchat read AAQAxtHFwMQ]

CUDACachingAllocator free_block assertion triggered rank 0 SIGABRT. Elastic agent correctly detected the crash and raised ChildFailedError to light.py main(). However, light.py main() (at revision 70fd858e, light_cli:5308) had no try/except on the error path — it fell through to Python's normal shutdown. During shutdown, Python attempted to join NCCL communicator threads. Those threads were stuck: rank 0 was dead, ranks 1–7 were still alive waiting for rank 0 in NCCL collectives that would never complete. The join blocked forever → process zombie → MAST never read the reply file → no new attempt created despite 100 retries available.

Root fix: D98638473 (landed 2026-05-21) wraps main() with try/except → exit_w_cleanup(1) → os._exit(), forcing the process to exit after writing the error. This base layer (upstream 2026-05-02) predated the fix by 19 days, so the fix was not present when S665454's instances occurred.

## Mitigation
Manual restart for each stuck instance. D98638473 confirmed applicable by Denny Zhang (2026-06-03); mlygao confirmed and closed SEV (2026-06-04). Base layer upgrade to include D98638473 required for permanent fix.

## Prevention
Add `[MVAI_EXIT]` logging at elastic agent exit path (D107459272, landed 2026-06-04) so future zombie jobs can be triaged in 1 minute:
- Log exists → EA exited, container still alive → MAST/TW oncall
- Log missing → EA hung, never exited → MVAI oncall
