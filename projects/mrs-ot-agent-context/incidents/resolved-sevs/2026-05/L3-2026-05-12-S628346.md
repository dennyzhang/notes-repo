## Root cause
[postmortem field] The light.py process for MVAI training jobs may not terminate successfully when unhandled exceptions trigger worker failures, specifically when non-joined non-daemon threads continue running in the process. TGIF publishing failures (Manifold race conditions, HH lowering errors) caused worker-level NCCL deadlocks. SJD correctly killed workers via SIGKILL, but the agent process survived because exit_w_cleanup() in light.py only ran on the success path. On ChildFailedError, Python's threading._shutdown() blocked indefinitely on stuck C++ threads (NCCL, DPP, publisher). Without the agent exiting, MAST never detected the job as failed and never retried — leaving it idle 6–28h per incident.

Additional layer [postmortem field]: The torch elastic watchdog timer resets the default SIGABRT handler then calls SIGALRM, which can invoke a registered SIGABRT handler that hangs. This prevented SIGABRT-triggered cleanup from completing on rank 0. Solution: JK rule to switch watchdog to SIGALRM path (D96542699).

Note: NCCL timeout is a RED HERRING (already in known_patterns.md ruled-out list) — NCCL timeout was a symptom of rank stall during publish, not the root cause.

[VERIFIED via gchat read spaces/AAQAhVAJDko: Dave Kotfis 2026-04-01 confirmed "hanging sigabrt handler on rank0 is still a possible failure mode"; Armand Sauzay confirmed "elastic agent not terminating — tupperware still marks healthy while agent hangs"]

## Mitigation
1. D98638473 — Adds `exit_w_cleanup()` on the error path in light_cli (base layer); agent calls `os._exit(1)` on ChildFailedError regardless of thread state. **KEY FIX**.
2. D97199931 — SIGKILL escalation in SJD: after SIGABRT to rank 0, waits 30s and escalates to SIGKILL if process still alive.
3. D96542699 — JK rule: switches watchdog to SIGALRM path instead of broken SIGABRT path (bypasses initFacebook C-level handler issue).
4. D95294551 + D95541181 — Hardened publish path: fixed Manifold write race conditions (most common failure trigger).
