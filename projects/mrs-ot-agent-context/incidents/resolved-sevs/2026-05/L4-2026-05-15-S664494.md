## Root cause
[sourced from overview field — postmortem root_cause field empty]

PyTorch upstream diff D104838289 (commit c02d4687f53e) introduced a TorchScript annotation mismatch in `torch.unique_consecutive`: the function `torch/functional.py:_consecutive_return_inverse_and_counts` is annotated as returning `Tuple[Tensor]` but actually returns `Tuple[Tensor, Tensor, Tensor]`. This annotation mismatch is caught at TorchScript model packaging time (not runtime), causing the `publish_multi_forward` step for mvai/umia_v1_igr IGR Tab T2I models (R11393.2, R11409.1) to fail deterministically. The call chain: `dper_lib/silvertorch/modules/serving/retrieval/li_cluster_selection_op.py:_select_clusters` → `torch.unique_consecutive(return_inverse=True, return_counts=True)`.

**Pattern match: P52** (PyTorch upstream TorchScript return-type annotation mismatch → conveyor publish block)
