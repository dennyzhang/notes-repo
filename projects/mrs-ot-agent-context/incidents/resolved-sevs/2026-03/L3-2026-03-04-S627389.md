## Overview
cogwheel_ig_ranking_esr_test on mvai/mvai_ig_ranking conveyor blocked for ~18 days (R6700-R7136) due to AOTI lowered snapshot export failure caused by D93984488 registering Hammer attention ops as @torch.library.custom_op. Remediated by D95149236 (temporary removal of @custom_op). Long-term fix in D95221103 (training/inference path split).

## Incident impact
The mvai/mvai_ig_ranking conveyor cogwheel_ig_ranking_esr_test was blocked for ~18 days (2026-02-14 to 2026-03-04). ESR model releases were delayed. Other cogwheel tests (LSR, Blackwell) were unaffected. No direct user-facing impact - this was a release pipeline validation failure.

## Root cause
D93984488 (Reland of D91791095) registered Hammer/HSTU attention forward functions as PyTorch custom_ops. This broke AOTI model lowering because the custom ops could not be traced by the AOTI export pipeline. The ESR cogwheel test requires AOTI-lowered snapshots, so it failed with 'Model requires a lowered snapshot (AOTI) but it was not found.' The original diff had been reverted for this reason, but the reland did not address the AOTI incompatibility.

## Remediation
D95149236 temporarily removed the @custom_op decorators from the attention forward functions, restoring direct function calls compatible with AOTI. D95221103 implemented the permanent fix by splitting attention functions into training (using torch.ops.hammer.* for PT2 compile) and inference (direct calls for AOTI export) paths.

## Prevention
Pre-land AOTI validation should be added for Hammer attention op changes. Changes registering functions as @torch.library.custom_op should be tested against both PT2 compile AND AOTI export paths. The reland process should require explicit verification that the original revert reason was addressed.
