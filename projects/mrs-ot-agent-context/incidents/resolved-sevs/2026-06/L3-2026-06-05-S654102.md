## Root cause
**Dual cause** [sourced from investigation_summary + gchat AAQAOJ3VA6I]:

1. **PRIMARY (P60 match):** `PublishRateLimiter.max_publishing_rate` was set to 2097152 bytes/sec (~2 MB/s) — insufficient for sparse streaming at 100% embedding deltas on a high-cardinality IG Reels model. BD writer divides this global rate by num_ranks (per `getMaxPublishingRate()=rate/numPublishers`), leaving each rank far below what the delta volume requires. Result: `_send_delta_via_quick_streaming` falls behind → QUEUE_LAG dogpile fires (`dogpile.0.light#native-main#bundle-runtime#cinder#...QUEUE_LAG`) → Manifold teardown cascade → SIGTERM/SIGUSR2 → crash.

2. **COMPOUNDING (related to S654768):** D100840142 (landed ~2026-04-14) disabled PyTorch Kineto's SIGUSR2 handler fleet-wide to protect inference jobs from a profiling storm. Without the handler, SIGUSR2 signals became fatal (OS default: terminate). The QUEUE_LAG-triggered watchdog signals were thus unhandled → crash instead of soft recovery.

Matches CL-(none) — no cluster entry yet. Matches P60 via PublishRateLimiter throttle mechanism. SIGUSR2 compounding factor is a secondary pattern (1 sample — below P-row threshold; log to learnings-ledger).
